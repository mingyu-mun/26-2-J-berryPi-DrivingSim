# 03. 데이터·통신 규약

이 시뮬레이터는 팀 모델 저장소의 두 규약을 따릅니다.
- **`docs/data-handoff.md`**: 세션 폴더 형식
- **`WEBBOARD_DATA_CONTRACT.md` v1.2**: 웹보드 이벤트

이 문서는 그 규약을 시뮬레이터에서 어떻게 적용했는지, 그리고 시뮬레이터 내부 통신(UDP)을 어떻게 정했는지 정리합니다.

**공통 원칙** (웹보드 규약 0장)
- 원본에 없는 값(생체값, AI 확률, 차량값, 졸음 라벨)을 그럴듯하게 만들어 넣지 않습니다.
- 값이 없으면 `null`로 둡니다. Unity 내부 UI 패킷만 예외로 `-1`을 씁니다.
- 출처를 항상 표시합니다.
  - 생체: `recorded` (기록 재생) / `live` (실측 모드)
  - 차량: `simulated` (시뮬레이터 합성)
- 화면의 상태는 `StateMachineV2.step` 출력만 표시합니다. UI가 따로 판정하지 않습니다.

## 1. Replay 세션 폴더

`Assets/StreamingAssets/Replays/<세션>/` (유니티 안, 빌드에도 포함) 또는 `SimLogs/bio/<세션>/`. `Tools/convert_recording.py` 또는 `gen_synthetic_bio.py`가 만들고, 메인 메뉴가 두 폴더를 모두 찾아 목록에 보여 줍니다. 이름이 겹치면 StreamingAssets 쪽을 씁니다.

| 파일 | 형식 | 비고 |
|---|---|---|
| `meta.json` | `{"dataset_id", "subject_id", "session_id", "role": "replay"\|"baseline", "fs": {"ecg": 435.33, "ppg": 100.66}, "duration_s": 2040.0, "is_rest", "prefiltered": false, "t_offset": 60.0, "source": {..., "range_s": [a, b]}}` | `fs`는 필수이며 채널마다 다를 수 있습니다. `role: baseline`이면 메뉴의 **기준 측정 파일** 목록에 나옵니다. `duration_s`가 없으면 파일 크기로 추정합니다. |
| `ecg.csv` | 헤더 `value`, 한 줄에 표본 하나 | **원신호**(ADC 값 그대로, 필터 없음). 결측은 빈칸입니다. |
| `ppg.csv` | 헤더 `value` | PPG 적외선 원신호 |
| `labels.csv` (선택) | `start_s,end_s,label[,source_marker]` | 화면에 '참고 라벨(자기보고)'로만 표시합니다. **모델 입력이 아닙니다.** |

**변환 결정 사항** (rec_20261118, 2026-11-18)
- ECG는 `ecg_1_라벨링.csv`의 `ECG원본`, PPG는 `ppg_1_라벨링.csv`의 `PPG적외선원본`을 씁니다.
- 두 채널 중 늦게 시작한 쪽에 맞춥니다. 그 시각이 `t_offset`이고, rec_20261118에서는 60.0 s입니다.
- 측정 프로그램의 타임스탬프가 묶음으로 들어오기 때문에 표본 간격이 일정하지 않습니다. 그래서 균일 간격으로 가정하고 다음과 같이 계산했습니다.

  $$f_s = \frac{N - 1}{t_{N} - t_{1}}$$

  - $N$: 채널의 표본 수
  - $t_1$, $t_N$: 첫 표본과 마지막 표본의 원본 타임스탬프 [s]
- 라벨은 '라벨링' 열에 블록이 끝날 때마다 찍힌 표시(예: `11~15분 졸음`)를 `[이전 표시, 이 표시)` 구간으로 바꾼 것입니다.

## 2. 시간축

| 이름 | 정의 |
|---|---|
| **세션 시각** `t_rel_s` | 서버가 받은 생체 표본의 길이입니다. 두 채널 중 짧은 쪽을 기준으로, $\min(n_{ecg}/f_{s,ecg},\ n_{ppg}/f_{s,ppg})$ 입니다. 측정 시각 기준이며 PC 수신 시각이 아닙니다. |
| 재생 시각 | 기록 기준 초입니다. 화면 `기록 재생 mm:ss`에 표시됩니다. Preroll을 켜면 세션 시각과 같고, 끄면 재생 시각 = 시작 위치 + 세션 시각입니다. |
| CAN 시각 | `BioReplay.ElapsedSec`(Play 후 경과)에 preroll 길이를 더해 세션 시각에 맞춥니다. |
| 판정 시각 | `WindowIn.t` = 창 끝 = 창 시작 + 30 s입니다. 판정은 10 s 간격이고, 출력은 창 끝 + 5 s(`causal`) 또는 + 140 s(`exact`)에 나옵니다. |

- Play 한 번이 세션 하나입니다. `session_id`는 `sim_YYYYMMDD_HHMMSS` 형식이며, 새 세션이 시작되면 상태 머신을 처음부터 다시 시작합니다.
- 서버가 세션을 받아들이기 전에 들어온 생체 표본은 Unity에 쌓아 두었다가 보냅니다. 표본이 빠지면 세션 시각이 틀어지므로 버리지 않습니다.

## 3. Unity ↔ 추론 서버 (UDP, 127.0.0.1)

UTF-8 JSON 한 개가 패킷 하나입니다. 서버가 늦게 떠도 되도록 Unity는 `hello`를 1초마다 반복해서 보냅니다.

### 3-1. Unity → 서버 (포트 5005)

| type | 주기 | 필드 |
|---|---|---|
| `hello` | 1 Hz | `session`, `participant`, `origin`(`recorded`/`live`), `replay`(세션 폴더 이름 또는 `live:<장치>`), `mode`(`causal`/`exact`), `fs_ecg`, `fs_ppg`, `replay_offset`[s], `preroll_dir`, `preroll_sec`, `baseline_dir`(기준 측정 파일 폴더, 비우면 자동 수집) |
| `bio` | 10 Hz 묶음 | `ecg: float[]`, `ppg: float[]`. 각 채널의 **원래 주기 원신호**이며, 직전 패킷 다음 표본부터 이어집니다. 한 묶음은 ECG 최대 2200 표본입니다. |
| `can` | 10 Hz 묶음 (50 Hz 표본) | `t[]`[s], `speed[]`[km/h], `steer[]`[핸들각 °, +오른쪽], `accel[]`·`brake[]`[0~1], `gear[]`(0=P 1=R 2=N 3=D), `turn[]`(−1 좌, 0, +1 우) |

- 서버는 `hello.session`이 바뀌면 새 세션을 만듭니다.
- `baseline_dir`가 있으면 서버가 그 폴더의 기록으로 개인 기준(RR 특징 중앙값·산포, 학생 기준 파형)을 먼저 정합니다 (`engine.use_baseline_recording`). 판정은 입력 0초부터 시작합니다.
- `preroll_sec > 0`이면 서버가 `preroll_dir`의 기록 중 `[replay_offset − preroll_sec, replay_offset)` 구간을 직접 읽어 먼저 넣습니다. 이때 세션 시각 0은 그 구간의 시작이 됩니다.
  - 자동 수집이면 Unity는 `preroll_sec = 시작 위치`(0초부터 전부)를 보냅니다.
  - 기준 파일이면 `min(시작 위치, 300)`(5분 특징 창 채우기)을 보냅니다.

### 3-2. 서버 → Unity (포트 5006): `ui` 패킷, 약 10 Hz

JsonUtility로 읽어야 하므로 평평한 구조이며, 값이 없으면 `-1`(문자열은 `""`)입니다.

| 묶음 | 필드 |
|---|---|
| 세션 | `session`, `mode`, `model_id`(`S1-EP`), `sm_id`(`v2`), `bio_origin`(`recorded`), `can_origin`(`simulated`/`unavailable`), `t_rel`, `preroll`, `decision_delay`, `error` |
| 기준 수집 | `base_status`(`waiting`/`collecting`/`ready`/`retry_required`), `base_source`(`auto`/`file:<이름>`), `feat_ready`(0~1, 세션 시각 / 300 s), `base_forced`, `clean_windows`, `required_clean`(20), `base_wait`(60), `base_max`(600), `base_a`, `base_b`, `n_windows` |
| 연결 | `ecg_rx`(최근 3 s 안에 생체 표본 받음), `can_rx`(2 s) |
| 상태 머신 출력 (`has_out=true`일 때) | `level`(-1/0/1/2), `level_name`, `candidate`, `frozen`, `score`, `p_used`, `confidence`, `channel`(`EP`/`PPG`/`none`), `confirmation_source`, `th_on`, `th_off` |
| 입력 | `p_ep`, `p_ppg`, `q_ecg`, `q_ppg`, `hr_ecg`, `hr_ppg`, `logit_ep`, `win_end`, `out_age`, `proc_ms` |
| 근거 | `z_names[3]`, `z_vals[3]`: 개인 기준 대비 \|z\|가 가장 큰 RR 특징. 모델 입력이며 ±5에서 잘립니다. |
| 이력 | `hist_t[]`, `hist_p[]`, `hist_lv[]`: 최근 120창 |
| 파형 | `wave_fs`(100), `ecg_w[]`, `ppg_w[]`: 최근 6 s를 저장소 공통 전처리(`prepare_channel`)한 뒤 화면용으로 중앙값을 빼고 표준편차로 나눈 값입니다. 필터 가장자리인 끝 1 s는 뺍니다. |

### 3-3. 라즈베리파이 → Unity (실측 모드, UDP 5010)

`LivePacket` JSON: `type="bio"`, `device`, `seq`, `t_dev`[s], `fs_ecg`, `fs_ppg`, `ecg[]`, `ppg[]` (원신호, 기본 10 Hz 묶음).
- 세션 시각은 받은 ECG 표본 수 ÷ `fs_ecg`로 계산합니다.
- 서버로 보낼 때 `origin=live`가 붙습니다.
- 자세한 내용과 전송 방식 비교는 [06_실측모드.md](06_실측모드.md)에 있습니다.

## 4. 웹보드 규약 v1.2 이벤트 (`SimLogs/ai/events_<세션>.jsonl`, 선택 시 `/api/events`)

저장소의 `driver_state/webboard_connector.py` 함수를 그대로 써서 만듭니다.

| 이벤트 | 주기 | `origin` | 내용 |
|---|---|---|---|
| `ai.decision` | 창마다 (10 s) | `recorded` / `live` | `model_id=S1-EP`, `state_machine_id=v2`, `bio_origin=recorded`, `can_origin=simulated`, `input`=WindowIn, `output`=StepOut(기준 수집 전에는 null), `confirmation_source`(CAN 판정이 없으므로 졸음 확정 시 `persistence`) |
| `system.status` | 1 s | `recorded` / `live` | `bio_baseline{status, clean_windows, required_clean_windows=20, elapsed_s}`, `can_baseline{status=unavailable}`, `connections{ecg, ppg, can, model}`(실제 수신 여부) |
| `bio.wave` | 1 s | `recorded` / `live` | 직전 1 s, `stage=common_preprocessed`, 100 Hz, `unit=a.u.`, `quality_ok=null` |
| `can.telemetry` | 10 Hz | **`simulated`** | 5절 매핑 |

## 5. CAN 신호 매핑 (`can.telemetry.payload`, origin `simulated`)

`Can list.xlsx`의 표현 범위로 맞춥니다. **실차 신호가 아니라 시뮬레이터 값입니다.**

| 필드 | 시뮬레이터 값 | 규칙 |
|---|---|---|
| `speed_kmh` | \|차속\| | 0~255 정수 (CARINFO 0x102 범위) |
| `steering_angle_deg` | 핸들각 (바퀴각 × 15, +오른쪽) | 0.1° 단위. 원본 표에 좌/우 부호 정의가 없으므로 시뮬레이터 기준을 따릅니다. |
| `steering_rate_deg_s` | Δ핸들각 / Δt | 연속된 두 관측값으로 계산합니다. |
| `accel_pedal_raw` | 가속 페달 0~1 × 254 | 정수 0~254 |
| `brake_pedal_raw` | 브레이크 0~1 × 127 | 정수 0~127 |
| `status_codes.GearPosition` | R→1, 정지(N)→2, 전진→3 | 0=P, 1=R, 2=N, 3=D |
| `status_codes.LTurnSig_Indi` / `RTurnSig_Indi` | 깜빡이 | 0/1 |
| `signal_times_s` | 모든 신호 같은 시각 | 시뮬레이터는 50 Hz로 한꺼번에 표본을 뜹니다. |
| `road_wheel_angle_deg`, `accelerator_pct`, `brake_pct`, `baseline_coverage_pct`, `rule_id`, `signal_map_id` | **null** | 환산식 미확정 / 알고리즘 없음 |
| `deviation_status` | `unavailable` | |
| **`can_drowsy`** | **null** | 검증된 CAN 졸음 규칙이 없습니다. 규약 6.1에 따라 규칙이 생기기 전까지 null입니다. |

## 6. 주행 로그 컬럼 (`drive_<ID>_<시각>.csv`, 50 Hz)

| 컬럼 | 단위 | 설명 |
|---|---|---|
| `wall_unix_ms` | ms | PC 벽시계 UTC. 생체신호와 맞출 때 이 값을 기준으로 씁니다. |
| `t_s`, `sample` | s, - | 기록 시작 후 시뮬레이션 시간(간격이 정확히 20 ms), 표본 번호 |
| `speed_kmh`, `accel_pedal`, `brake_pedal` | km/h, 0~1, 0~1 | 차속(후진은 음수), 페달 |
| `steer_input`, `steering_wheel_deg`, `wheel_angle_deg` | -1~1, °, ° | 조향 입력, 핸들각(= 바퀴각 × 15), 앞바퀴각 |
| `yaw_rate_dps`, `long_accel_mps2`, `lat_accel_mps2` | °/s, m/s² | 요레이트(+오른쪽), 종·횡가속도 |
| `engine_rpm`, `gear` | rpm, - | **모사값** (속도 구간으로 만든 값) |
| `turn_signal` | -1/0/1 | 깜빡이 |
| `track_s_m`, `lap` | m, - | 트랙 진행 거리, 랩 |
| `lane`, `lateral_pos_m`, `lane_offset_m`, `heading_error_deg`, `road_curvature` | -, m, m, °, 1/m | 차로(0 = 도로 밖), 횡위치, **차로 중심 대비 편차**, 헤딩 오차, 곡률 |
| `lane_departure` | 0/1 | \|편차\| > (3.5 − 1.8)/2 = 0.85 m |
| `marker` | - | M 키 마커 번호 |
| `ai_level`, `ai_p_used` | -, 0~1 | 그 순간 화면에 보인 상태 머신 level, p_used (판정 전 -9 / -1) |
| `bio_replay_t_s` | s | 재생 위치 |

`events.csv`에는 기록 시작/정지, 마커, 깜빡이, 리셋, 랩이 남습니다. `meta.json`에는 참가자, 조향 방식, 트랙, 물리 설정이 남습니다.

## 7. 데이터 취급

- `SimLogs/`와 `Assets/StreamingAssets/Replays/*`(README 제외)는 `.gitignore` 대상입니다. 원신호, 주행 로그, 판정 로그, 운전자 프로필은 저장소에 올리지 않습니다.
- 모델 가중치는 팀 모델 저장소의 `models/README.md` 조건을 따릅니다. WESAD로 학습한 가중치는 비상업 용도로만 씁니다.
